# P1 FR-011 à FR-013 — import éditorial et frontières externes bornées

Date : 2026-09-18
Branche : `fix/p1-bounded-external-io`
Base : `92ab864`

## Résultat

- **FR-011** : aucune fixture ne peut plus écrire directement dans
  `articles_projection`. L'import historique est désactivé par défaut, versionné,
  explicitement activé par l'opérateur et traverse le port Studio puis les
  commandes Article. Les identifiants stables permettent la reprise par
  `command_status`.
- **FR-012** : RSS et YouTube utilisent la même frontière HTTP bornée. Les URI
  avec credentials/fragments, adresses privées/loopback/link-local et redirects
  sont refusées. Le délai couvre la consommation du corps ; octets et nombre
  d'items sont bornés.
- **FR-013** : le timeout du binaire ticket est une deadline globale. stdin,
  stdout et stderr sont concurrents et bornés ; les tâches et processus sont
  nettoyés sur toute sortie.

## Architecture

L'import est un adaptateur primaire opt-in d'`adminImportContext`. Il appelle
`ImportVersionedArticleSeeds`, lequel ne connaît que `ArticleAuthoringPort`.
L'adaptateur secondaire existant traduit ensuite vers les commandes du BC
Article. Il n'existe plus de port `insertSeed` sur le repository de projection.
L'ACL du runner traduit explicitement la taxonomie historique (`Terroir`,
`Nutrition`, `Équipement`, etc.) vers la taxonomie Article actuelle. Un tag
legacy inconnu interrompt l'import avant commande au lieu d'élargir implicitement
l'invariant du domaine.

Les protections HTTP restent dans les adaptateurs secondaires
`editorialIntelligenceContext`; aucune URI, réponse HTTP ou règle DNS ne fuit
dans le domaine. Les bornes du processus ticket restent dans l'adaptateur du
provider et ne modifient ni le process manager durable ni ses leases.

```text
git diff --check
```

Résultats consolidés :

- suite Maven standard : **438 tests**, 0 échec, 0 erreur, 0 ignoré ;
- gate backend de release, incluant les tests `*IT`, l'infrastructure et les
  verticales PostgreSQL : **609 tests**, 0 échec, 0 erreur, 0 ignoré ;
- compilation/package : succès.

Le gate de release signale encore, après le succès des tests, que Surefire doit
terminer son JVM fork après 30 secondes. Des workers `projection-sync` tentent
également de valider des connexions PostgreSQL déjà fermées pendant l'arrêt de
certains contextes de test. Cela n'a produit aucune erreur de test ni perte de
preuve pour FR-011 à FR-013, mais indique une dette distincte de fermeture des
executors/listeners de projection ; l'avertissement n'est pas présenté comme
corrigé par ce lot.

La première tentative de `VersionedArticleSeedImportIT` a échoué avant Spring,
Docker Desktop étant arrêté. Après démarrage explicite, le test a révélé le
contrat de tags legacy incompatible ; l'ACL a été corrigée, puis le test a été
relancé avec succès contre PostgreSQL 13 Testcontainers. Cette séquence est
conservée pour ne pas masquer l'échec intermédiaire utile.

## FlowAtlas

FlowAtlas Java a été utilisé avec la requête bornée
`fragments-java-external-request.json` :

```json
{"query":"ProcessBuilder","adapter":"java","kind":"External","limit":5}
```

`find` retrouve `local-process:java.lang.ProcessBuilder` à la ligne 85 du
provider. `context` (both, profondeur 4) retourne un graphe complet selon ses
limites, 2 nœuds et 1 arête, du worker planifié vers la frontière processus.
Le format `schemaVersion: 2`, `frontierComplete`, `limitsReached` et
`serializedBytes` rend désormais la complétude beaucoup plus exploitable.

Limite constatée : le graphe contracte encore le provider et relie directement
le worker à `ProcessBuilder`. Il localise très vite la frontière et son appelant
métier, mais ne permet pas d'auditer les deadlines, les flux ni le cleanup ; la
lecture du provider et des tests reste indispensable. Aucun scan Java générique
du dépôt n'a été lancé.

## Rollback

Le rollback du code réactive l'ancien runner implicite et est donc déconseillé
sur une base fraîche. Si un rollback applicatif est indispensable, conserver
`ARTICLE_SEED_IMPORT_ENABLED=false`. L'import explicite n'efface aucune donnée ;
ses commandes et événements restent auditables. Les limites HTTP/processus sont
configurables, mais ne doivent pas être neutralisées pour contourner un provider
défaillant.
